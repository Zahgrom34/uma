# Changelog

05.10.2026 — billz-v4: The Billz sync's variant grouping extended from `parent_id` only to parent-group ∪ name-stem (`name.split(' / ')[0]`, case-insensitive), because the merchant's BILLZ 2 catalog stores every size/color as a standalone row with a unique `parent_id` — parent grouping had degraded to groups of one. A matched product now aggregates all same-name rows: per-size qty summed across colors (was last-row-wins), size set = group union, photos imported from any variant card (the «photos only in the smallest-size card» workaround is obsolete), and `billzSku` accepts any variant's артикул. Pricing rule unchanged; the disagreement warning now also fires across color rows, with priceless rows skipped in the comparison (accepted). Implementation confined to `api/src/billz/billz.service.ts` + e2e; no wire or UI change, QC trimmed to api e2e + live smoke per contract. Live-verified: YYS-42424 → 6-row stem, stock 118 = S57+M46+L15 across 2 colors; prod after deploy 32/32 synced, importedPhotos 2 then 0, kurtka gallery 8 unique photos from both color rows; api e2e 65/65. Deployed 05.10.2026 as image `uma:billz-v4`, commit `816be83`. Details in `docs/features/billz-v4.md`.

04.10.2026 — catalog-sync-v1: The storefront's category plumbing is now driven by the API bundle's `categories` (slug + ru/uz/en names + sortOrder) instead of hardcoded Russian strings. Menu, `/catalog/<slug>` routes, filter tabs, breadcrumbs, size logic (no size selector for accessories/«other» such as decor; shoes numeric; wearables XS–XL + size finder), search and related-product suggestions all key on `categorySlug` — a category added or renamed in the CMS appears on the storefront after reload with no code change (verified live). Legacy routes (jeans/polo/tshirts/shirts/knitwear/jewellery/scarves) alias to real categories; «Новинки» falls back to the full catalog when nothing is tagged New; tab selection resets between routes; the menu tab row wraps instead of clipping (the one permitted styles.css change, under a rework amendment). One contract conflict (`more` key collision → `moreCategories`) handled per process. QC surfaced prod data incidents, fixed live: Billz shopIds pointed at the empty «Website» shop (all-shops re-sync restored stock), 4 stale Sale tags cleared, 26 imports tagged New, naming fixes. Deployed as commit `2115cf1` (GH Pages green) and to `/var/www/uma` behind Caddy on 49.13.106.185; `content-snapshot.json` regenerated from the live prod bundle. Details in `docs/features/catalog-sync-v1.md`.

04.10.2026 — billz catalog import to prod: The merchant's Billz catalog brought into the production CMS — 26 products created from Billz rows, 6 mapped to existing UMA products, and the 16 original demo products set to draft; a new «Декор» category added for the imported vases. Prod now serves 32 Billz-backed products in 11 categories, which is what motivated catalog-sync-v1 (the storefront only knew the old 10).

03.10.2026 — billz-v3: The manual Billz sync now also imports product photos from the matched BILLZ 2 rows (`photos: [{photo_url, sequence, is_main}]`, public DO Spaces URLs) in append-missing mode: Billz photos are appended AFTER the product's curated CMS photos, never replacing or reordering them, deduplicated three ways (sourceUrl reuse, content-hash in the media pipeline, already-attached mediaIds), capped at 10 per product per run. Downloads go through a new `BillzClient.downloadPhoto` seam (15 s, 2 attempts, 10 MiB cap) BEFORE the sync transaction; per-photo failures produce Russian warnings and never abort the run. `BillzSyncReport` gains optional `importedPhotos`; the Billz card shows «Загружено фото: N» only when the field exists. Append-missing was the user's fixed choice — fill-empty would have been a no-op since product creation requires at least one photo. Live-verified: ZPH-30325 → uma-sequin-dress appended 1 photo then 0 on re-run, product restored exactly; api e2e 64/64. Lean run with the billz-v2-style QC trim. Details in `docs/features/billz-v3.md`.

03.09.2026 — billz-v2: The billz-v1 sync adapted to the merchant's actual platform, BILLZ 2 (api-admin.billz.ai) — the live smoke showed the secret token authenticates there, not against BILLZ 1. `BillzClient` rewritten: secret-token login → cached bearer access token with one 401 re-login, paginated `GET /v2/products`, `GET /v1/shop`. Sync remapped: `parent_id` variant grouping (any variant's артикул matches the whole group), sizes from the razmer/размер/size product attribute, qty summed from `shop_measurement_values` over selected shops, pricing from `shop_prices` with `promo_price` driving `sale`/`oldPrice`. Settings reduced to `{secretKey (token, sentinel kept), shopIds}`; the CMS card now shows «Секретный токен» plus a checkbox list of real shop names via new `GET /api/admin/billz/shops` (username/issuer/comma-IDs removed). Live-verified on the real account: 276 rows, 4 shops, real sync applied exact retail price and stock with Russian warnings, test product restored, public bundle leak-free; api e2e 61/61. Lean run at ~10% weekly budget with user-sanctioned QC trim (playwright-qa + orchestrator live smoke; no bug-hunter/planner-assessor). Details in `docs/features/billz-v2.md`; API notes in `docs/reference/billz2-api-notes.md`.

03.09.2026 — billz-v1: Manual stock + price sync from the merchant's BILLZ 1 POS into the content API. A new `api/src/billz/` module signs a self-signed HS256 JWT and calls `products.get` over JSON-RPC 2.0, matches Billz rows to UMA products via a new `Product.billzSku` field («Артикул Billz» in the product editor), merges per-size rows, applies sale-coherent pricing (`discountAmount` → `sale`/`oldPrice`) and per-size availability with a low-stock threshold of 3, all in one transaction with a single content invalidation. Credentials live in a new CMS Settings «Интеграции» → Billz card with a write-only secret (GET masks it, empty PUT keeps it — survives other cards' read-modify-write saves), test-connection and sync buttons, and a persisted last-run report; none of `billz`, `billzSync`, or `billzSku` leaks into the public bundle (double-verified). Manual trigger only — no cron, no order push, no catalog import. Shipped with a 0.5-iteration fix pass (ru-named sync warnings, de-jargoned card copy); api e2e 58/58 green; live smoke on the real SECRET_KEY pending the key's arrival. Details in `docs/features/billz-v1.md`.

16.08.2026 — cms-v2: Full CMS↔storefront pairing. The public content bundle switches from hour-long stale-while-revalidate caching to `Cache-Control: no-cache` with a strong ETag, and the storefront sends a plain simple GET (no manual `If-None-Match` — that header caused a CORS-preflight rejection from non-allowlisted origins), so a CMS edit is visible after one reload from any origin, GH Pages included. The storefront now consumes `bundle.uiStrings` (all 199 keys merged over the bundled literals, which stay as the API-down fallback), making footer labels, hero overlay text, and the rest of the site copy live-editable in «Тексты сайта». The homepage hero becomes manageable: mp4 upload in the media library (`ftyp` magic-byte check, ≤50 MB, stored verbatim), `settings.hero` validated as 1 video XOR 1–3 images, a new «Главная страница» screen for hero media and overlay strings, hero-in-use media deletes blocked with 409, and a «Соцсети» card in Настройки for the five icon-backed platforms. App.jsx changed by exactly four pinned edits. Shipped after one BLOCK (the preflight bug above) resolved by a lightweight fix round; api e2e 47/47 green. Details in `docs/features/cms-v2.md`.

15.08.2026 — cms-v1: First release of the UMA CMS. A NestJS + Prisma + SQLite API (`api/`) becomes the source of truth for all storefront content — 21 products with ru/uz/en translations, 10 categories, per-size stock, a local webp media library, 5 info pages, the UI-string catalog, and commerce settings — behind cookie-JWT auth with one seeded admin. A shadcn/ui admin panel (`cms/`, Russian chrome) covers products, categories, media, pages, site copy, and shipping settings. The legacy storefront now loads content at runtime from `GET /api/public/content` with a three-tier fallback (live API → localStorage cache → committed snapshot); an idempotent import script seeds everything from the legacy sources and localizes the Unsplash images. Shipped after three court iterations (two BLOCKs fixed: broken saves from contract wire-shape faults, plus two size-data bugs in the product form); all 23 acceptance criteria pass. Details in `docs/features/cms-v1.md`.
